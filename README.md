# Crypto Trading Bot — Backtesting Engine + Paper Trading (Python)

A complete, working crypto trading bot sample: a backtesting engine with
realistic cost modeling, two classic strategies, and a paper-trading mode
that runs the **same strategy code** against live public market prices.

No API keys needed for anything except going live (which stays disabled
by default).

## What was actually run

- **Data:** 2,871 real BTC/USDT 1-hour candles (2026-05-18 → 2026-09-15,
  ~120 days), fetched from the Binance **public** klines endpoint
  (`data/btcusdt_1h.csv`). No API key required.
- **Backtest** (`python run_backtest.py`, $10,000 starting equity,
  0.10% taker fee + 0.05% slippage per side, signals executed at the
  next bar's open — no lookahead):

| Strategy | Total return | Sharpe (ann.) | Max drawdown | Trades | Win rate | Fees paid |
|---|---|---|---|---|---|---|
| SMA crossover (20/50) | **+4.01%** | +0.58 | −14.57% | 62 | 35.5% | $611.99 |
| RSI mean-reversion (14/30/70) | **+0.07%** | +0.16 | −21.08% | 29 | 78.6% | $274.01 |
| Buy & hold (benchmark) | −1.38% | — | — | — | — | — |

- Full per-trade log and equity curves are in `backtest_report.txt`
  and `equity_curve.csv` — generated by the real run above, not hand-written.
- **Paper trading** (`python paper_trade.py`) was run live on 2026-09-15: it
  pulled public prices from the Binance public API, computed the RSI
  signal, and "bought" 0.131808 BTC at $75,830.17 into a paper portfolio
  (see the committed `paper_state.json`). No real orders, ever.

## Architecture

```
fetch_data.py      public Binance klines -> data/btcusdt_1h.csv
run_backtest.py    CLI: runs both strategies, writes backtest_report.txt
                   + equity_curve.csv
paper_trade.py     live paper trading loop (public prices only)
bot/
  data.py          CSV -> clean DataFrame
  indicators.py    SMA + Wilder's RSI in numpy
  strategy.py      Strategy interface: emits TARGET POSITIONS (0/1),
  strategies.py    never orders — so the same code runs in backtest
                   and paper trading
  portfolio.py     cash/BTC accounting, taker fee + slippage, dust filter
  engine.py        backtest loop (signal on bar t -> fill at bar t+1 open)
  metrics.py       return, Sharpe, max drawdown, win rate, round trips
live/exchange.py   live-trading seam — DISABLED unless you add API keys
```

The key design decision: strategies output *target positions*, not orders.
Execution (timing, fees, slippage, order sizing) lives in one place
(`Portfolio` / the engine), so a strategy can't accidentally cheat with
lookahead and the identical logic drives both backtesting and paper trading.

## The strategies

- **SMA crossover (20/50)** — trend following: fully long when the
  20-period SMA is above the 50-period SMA, flat otherwise. Rides
  sustained moves; whipsaws in sideways markets.
- **RSI mean reversion (14, 30/70)** — buys when the 14-period RSI
  drops below 30 (weakness), exits when RSI rises above 70 (strength),
  holds otherwise. High win rate, but a few deep losers.

Both are long/flat only — no leverage, no shorting.

## Run it

```bash
pip install -r requirements.txt

# 1. fetch fresh data (public endpoint, no key)
python fetch_data.py --days 120

# 2. backtest both strategies
python run_backtest.py

# 3. paper-trade the RSI strategy on live public prices
python paper_trade.py --strategy rsi --iterations 3 --interval 10

# continuous paper trading, one check every 5 minutes:
python paper_trade.py --strategy sma --iterations 1000000 --interval 300
```

## Going live (disabled by default)

`live/exchange.py` defines the seam (`get_price`, `market_buy`,
`market_sell`) and refuses to instantiate until you set
`LIVE_TRADING_ENABLED=1` with `BINANCE_API_KEY` / `BINANCE_API_SECRET`
in the environment. Production hardening a client would want next:
signed REST calls (or ccxt), idempotent order placement, position
reconciliation on startup, and kill-switches.

## Scope note (honest)

This is a demonstration sample, not a profitable-trading claim. The
numbers above are what these two textbook strategies actually produced
on this specific 120-day window — modest, and they would look
different on any other window. Backtests model fees and slippage but
can't model thin order books, exchange outages, or regime changes.
